# 搜索页完整对齐 H5 设计

## 目标

在保留 App 离线下载、离线拍照和本地回显能力的前提下，使搜索页的搜索、筛选、分页、下载、合并、拆分、解锁、复制当前验货和复制合并验货流程与 H5 保持一致。

## 架构

搜索页面只负责页面状态编排、弹层开关和导航。可测试的参数构造、日期边界、本地覆盖远程、合并资格判断、拆分结果去重和计划 ID 提取放入 `domain/searchViewModel.uts`。远程操作、返回值校验、本地记录清理和下载落库编排放入 `services/planOperationService.uts`。HTTP 路径及请求参数统一由 `api/planApi.uts` 提供。

卡片组件继续负责展示和操作入口，但不直接实现搜索页的远程业务流程。卡片通过语义化事件把解锁、复制、复制合并和拆分操作交给页面。筛选、合并、拆分、复制等重复视觉结构拆成独立组件，避免搜索页堆积大段模板。

## 数据流

1. 页面根据关键字、状态、验货类型和日期构建与 H5 相同的搜索参数。
2. `planApi.searchPlans` 使用 `current`、`size` 分页查询，当前页结果直接替换。
3. 页面读取本地计划，同 ID 本地记录完整覆盖远程记录，保证下载、锁定和离线编辑状态不丢失。
4. 下载、合并后下载、拆分项下载和复制后下载统一调用 `planDownloadService.downloadToLocal`。
5. 每次本地数据变化后重新读取仓库并覆盖当前搜索结果，使卡片立即显示已下载状态。

## 操作规则

- 合并：仅允许 `lockFlag=0`、`status=0`、`mergeType!=2` 且检查类型一致的计划；至少选择两条；同一组合并项保持工厂号、货类和检查类型一致。
- 拆分：仅允许 `mergeType=2`、`lockFlag=0`、`status=0`；先按 `parentPlanId` 查询预览，再调用拆分接口，结果可逐项下载。
- 解锁：调用 `/api/reports/generate/release/{planId}?reportDeleteFlag=0`；成功后删除关联本地记录，并把当前远程结果恢复为未锁定已定计划。
- 复制：必须选择检查类型和清单；当前验货使用 `copyFlag=1`，合并验货使用 `copyFlag=2`；复制成功后允许立即下载并保存本地。
- 筛选：状态映射为 `0/1/3`；开始日期转换为当天 `00:00:00.000`，结束日期转换为当天 `23:59:59.999`，均提交 ISO 字符串。

## 错误处理

所有远程操作都防止重复提交，并优先显示接口错误信息。接口返回缺少关键 ID、下载数据为空、合并选择不足或不符合资格时，在调用后续接口前直接阻止。操作失败不修改本地列表；本地保存失败时不显示已下载状态。

## 测试

- ViewModel 测试覆盖搜索参数、日期边界、本地覆盖、合并资格、拆分去重和计划 ID 提取。
- API 测试覆盖所有新增接口路径、方法、查询参数和请求体。
- Service 测试覆盖合并、拆分、复制、解锁、关联本地记录删除及下载委托。
- 页面契约测试覆盖搜索页组件接线、日期筛选、语义化业务事件和无下拉刷新。
